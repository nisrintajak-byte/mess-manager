- 2026-10-18 — v0.2 is backward compatible: v0.1 RPCs (add_expense, update_expense) keep their signatures and delegate to new create_expense / edit_expense, so the v0.1 preview keeps working on the shared database. No DROP/DELETE in migrations (connector blocks them).
- 2026-10-18 — Cycles are date ranges per Room (daily; weekly Mon–Sun; monthly calendar month), created lazily up to today by the server in the Room's time zone; the first cycle starts on the Room's creation date.
- 2026-10-18 — "Equal, pro-rated by stay" = an expense is shared equally by members active on its date (join/leave days count). Over a cycle this charges each member only for their stay. Alternative of per-day weighting inside one expense rejected as surprising for users.
- 2026-10-18 — Settlement can be generated for an ended cycle, or early "up to yesterday" (today's entries move to a new cycle) so Admins and testers need not wait for month end. Earlier open cycles must be settled first.
- 2026-10-18 — Lock enforced by DB triggers on expenses, splits and participants; settlements and settlement lines are immutable. Corrections = Admin adjustment in the open cycle, same payer and sharers, linked to the original; reductions stored as positive amount + is_credit (keeps v0.1 checks).
- 2026-10-18 — Payment line status: pending → awaiting → partial → paid (confirmed sum ≥ amount owed); rejected payments return the line to its previous state. Claims and Admin records cannot exceed what is still owed.
- 2026-10-18 — Currency change allowed only when the current cycle has no expenses and all earlier cycles are locked; time-zone / cycle-type changes apply immediately in that same "quiet" state, otherwise from the next cycle (shown as pending).
- 2026-10-18 — Two web previews: stable (version under founder test) at /mess-manager/ and next (version in progress) at /mess-manager/next/, both smoke-tested in a real browser after each deploy.
- 2026-10-18 — "Paid by" is always the member who adds the expense (founder): no payer picker in the app, and the server ignores any payer sent by a client; edits never change the payer. Prevents disputes from wrong or same-named selections. (PRD §10 "Paid By" field kept, filled automatically.) Paying on someone else's behalf → that person adds it themselves.
- 2026-10-18 — Identical member names in a Room are shown with a join-order number (Lenovo1, Lenovo2, …), computed server-side (room_member_labels) so every viewer sees the same labels; numbers never change when someone leaves (founder).
- 2026-10-18 — Notifications are created by database triggers on every write path (members, expenses, rooms, settlement lines, payments, flags, needs) so no event can be missed; the app renders the text in the reader's language from kind + payload. Push goes through pg_net → Expo Push API; failures never block the action and the in-app inbox is always the fallback.
- 2026-10-18 — Optional notifications: expense added/edited/deleted and Need Request events. Everything about membership, money, settlement, payments and disputes is mandatory.
- 2026-10-18 — Settlement due date in notifications = 7 days after generation (Room setting later if needed). Acknowledgement states: Delivered (notification created) → Seen (opened) → Acknowledged (button).
- 2026-10-18 — Disputes record the decision only; the actual correction is an edit (open cycle) or an adjustment (locked cycle), keeping one audited way to change money.
- 2026-10-18 — Push tokens are deactivated (not deleted) on sign-out so shared phones stop receiving the previous user's notifications.
- 2026-10-18 — /next/ preview tracks the newest version branch (now v0.3, a superset of v0.2).
- 2026-10-18 — v0.1–v0.3 merged into main (v0.3 is a superset); tags cannot be pushed from the workspace (proxy blocks them), so version branches + CHANGELOG are the markers. Previews: stable `/` = main, next `/next/` = newest version branch.
- 2026-10-18 — Themes: light, dark, sand, ocean; palettes in one file; `themedStyles` recomputes styles and the app remounts on change. All palettes unit-tested for WCAG AA contrast.
- 2026-10-18 — RTL: web uses `dir`; phone mirrors layouts in JavaScript (rows reversed, left/right swapped, navigation `direction`) with Android's own mirroring off, so language changes apply instantly with no restart (founder request).
- 2026-10-18 — Ar/Ur/Hi texts are machine-drafted placeholders; tests only guard key/placeholder parity. Professional human translation remains a launch blocker (PRD §16.2).
- 2026-10-18 — App Lock: salted, iterated SHA-256 PIN hash in phone secure storage; wrong-PIN delay; "Forgot PIN" = sign out (wipes lock). Sensitive actions (remove member, delete Room, change password) re-ask password (PIN for Google-only accounts) regardless of App Lock.
- 2026-10-18 — Google users start with consent 'unknown'; server blocks Rooms (`profile_incomplete`) until `complete_profile` (18+, consent). Supabase auto-links a verified Google email to an existing same-email account; PRD asks for password entry first — open question, and risky while email confirmation is OFF (testing), so Confirm email must be ON at launch.

## v0.5 — Offline storage and sync design
- Used AsyncStorage JSON cache instead of SQLite: simpler, no native build step, enough for read-copies and a small queue.
- Outbox item id is the idempotency key. Online first; queue only on network errors; server rule errors are shown to the user, never queued.
- Entries made while a cycle locked meanwhile become late entries (original date kept, flagged). Stale edits/deletes become conflicts the user resolves.
- Offline balances are labelled Estimated; official totals only from server.
