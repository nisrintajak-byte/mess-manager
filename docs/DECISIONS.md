# Decisions

Format: date — decision — why — alternatives considered

- 2026-10-18 — Use PRD §6 stack: Expo (React Native) + TypeScript strict + Supabase (Postgres, RLS, Auth, Storage, Edge Functions) — specified in PRD; one codebase, managed backend suits a non-technical founder — Flutter + Firebase (rejected: PRD already chose stack).
- 2026-10-18 — Android first, iOS post-v1 — PRD §25.2 lists iOS in parking lot — simultaneous iOS (rejected: cost/time).
- 2026-10-18 — v0.1 is English-only but every string goes through i18n files from day one — avoids rewrite when adding AR/UR/HI in v0.4 — hard-coded strings (rejected: violates §16.2).
- 2026-10-18 — v0.1 uses simple equal split among currently approved members; pro-rated-by-stay and cycles arrive in v0.2 — keeps first MVP small and testable — full engine in v0.1 (rejected: too large for first slice).
- 2026-10-18 — Original PRD kept as PDF plus extracted markdown; PRD changes recorded here, not in PRD.md.
- 2026-10-18 — npm registry is blocked in the Claude workspace, so dependencies are generated by a GitHub Actions workflow (`bootstrap-deps.yml`, triggered by editing `.github/bootstrap-request`) that commits package.json + lockfile — keeps versions Expo-SDK-compatible without local npm — hand-written versions (rejected: risk of wrong versions).
- 2026-10-18 — Clients get SELECT-only table access; every write goes through SECURITY DEFINER Postgres functions that re-check permissions with server time — enforces PRD rules (approval, 30-min edit, Last Admin, audit) in the database, not just the app, and is ready for offline-sync re-validation — direct table writes with RLS policies (rejected: harder to enforce multi-step rules).
- 2026-10-18 — Join codes: 8 chars from an alphabet without 0/O/1/I — easy to read aloud and type.
- 2026-10-18 — Country names (en/ar/ur/hi) from Unicode CLDR, zones from IANA tzdata; generated into src/data/countries.json by scripts/generate-countries.py.
- 2026-10-18 — Reuse founder's existing Supabase project `egylgjgimuytmnmrvzhs` (ap-south-1). Old empty tables from an earlier attempt moved to private schema `legacy_attempt` (not deleted; connector blocks destructive DDL without on-screen approval) — founder approved — new project (rejected: free plan limit).
- 2026-10-18 — On edit, expense shares of members no longer sharing are set to 0 instead of deleted — avoids DELETE statements and keeps a full record; UI hides zero shares.
- 2026-10-18 — Under-18 signup is blocked in v0.1 with a "coming soon" message until the parental-consent flow (v0.7) exists — PRD §20.4 forbids activating minors without verified parent consent.
- 2026-10-18 — Web preview hosted on GitHub Pages (repo is public; free) so the founder can test on any phone browser — Expo Go (rejected for first test: needs dev server); EAS internal build planned before launch.
- 2026-10-18 — Supabase publishable key + URL are committed (public by design; RLS protects data). Service-role key never stored in repo.
- 2026-10-18 — PRD §7.1 "5 failed logins → 15-min lock": v0.1 relies on Supabase Auth rate limits; an exact per-account lockout needs an Auth hook — tracked for v1.0 hardening.
- 2026-10-18 — TESTING_MODE (founder request): simple passwords (6+ chars) and Supabase email confirmation OFF during testing, to save testing time; under-18 block and all other rules unchanged. Revert before launch (v1.0 task).
- 2026-10-18 — Expense category removed from the UI (founder): picking a category on every entry is extra work and lists never fit every case. PRD §10 field kept in the database (stored as 'general') so reports or auto-categorisation can use it later without a migration.
- 2026-10-18 — v0.2 is backward compatible: v0.1 RPCs (add_expense, update_expense) keep their signatures and delegate to new create_expense / edit_expense, so the v0.1 preview keeps working on the shared database. No DROP/DELETE in migrations (connector blocks them).
- 2026-10-18 — Cycles are date ranges per Room (daily; weekly Mon–Sun; monthly calendar month), created lazily up to today by the server in the Room's time zone; the first cycle starts on the Room's creation date.
- 2026-10-18 — "Equal, pro-rated by stay" = an expense is shared equally by members active on its date (join/leave days count). Over a cycle this charges each member only for their stay. Alternative of per-day weighting inside one expense rejected as surprising for users.
- 2026-10-18 — Settlement can be generated for an ended cycle, or early "up to yesterday" (today's entries move to a new cycle) so Admins and testers need not wait for month end. Earlier open cycles must be settled first.
- 2026-10-18 — Lock enforced by DB triggers on expenses, splits and participants; settlements and settlement lines are immutable. Corrections = Admin adjustment in the open cycle, same payer and sharers, linked to the original; reductions stored as positive amount + is_credit (keeps v0.1 checks).
- 2026-10-18 — Payment line status: pending → awaiting → partial → paid (confirmed sum ≥ amount owed); rejected payments return the line to its previous state. Claims and Admin records cannot exceed what is still owed.
- 2026-10-18 — Currency change allowed only when the current cycle has no expenses and all earlier cycles are locked; time-zone / cycle-type changes apply immediately in that same "quiet" state, otherwise from the next cycle (shown as pending).
- 2026-10-18 — Two web previews: stable (version under founder test) at /mess-manager/ and next (version in progress) at /mess-manager/next/, both smoke-tested in a real browser after each deploy.
- 2026-10-18 — "Paid by" is always the member who adds the expense (founder): no payer picker in the app, and the server ignores any payer sent by a client; edits never change the payer. Prevents disputes from wrong or same-named selections. (PRD §10 "Paid By" field kept, filled automatically.) Paying on someone else's behalf → that person adds it themselves.
- 2026-10-18 — Identical member names in a Room are shown with a join-order number (Lenovo1, Lenovo2, …), computed server-side (room_member_labels) so every viewer sees the same labels; numbers never change when someone leaves (founder).
